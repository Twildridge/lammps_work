# Building Input Data Files

[← back to README](../README.md)

A gel simulation starts from a `.data` file: a text file with every atom's position and type and the bond topology. The files are built on the Mac with the Jupyter notebooks in `scripts/` (a notebook is a Python document run one cell at a time; `jupyter lab` in a terminal opens them) or with the converter scripts in `scripts/lib/`. They are kept in `lammps_data_files_local/` next to the repo, catalogued in its `README.md`, and copied to `~/Documents/lammps_data/input_data/` on the cluster.

### Which notebook or script to use

The notebooks live in `scripts/`; the Python modules they import (converters, plate builder, CLI tools) live in `scripts/lib/` (since 2026-10-01), which the notebooks add to `sys.path` themselves.

### Running the isolated-gel converter from the Terminal (2026-10-14)

`lib/add_more_plates_to_gel.py` has no notebook: run the script. If you only ever use JupyterLab, the easiest
terminal is the one inside it (**File → New → Terminal**); it already has the Python that runs your notebooks.

```bash
cd "<your lammps_work folder>/scripts/lib"            # quote the path, it has spaces
python add_more_plates_to_gel.py --layout x_plates \
    --input ../../../lammps_data_files_local/final_config_slab_support_5beads_tall_rho04_nowalls_1.0_1.0_8000000.data
```

`--layout six_plates` builds the `compress_slab` file, `--help` lists every option (bath margins, reservoirs,
plate park gap and overhang, `--no-log`, `--no-png`). `python` must be the Anaconda Python that runs JupyterLab
(`which python` shows which is active; `conda activate base` switches to it; on Dylan's Mac it is
`/opt/anaconda3/bin/python`). The same line works in a notebook cell with a leading `!`, with the path relative to
the notebook (`!python lib/add_more_plates_to_gel.py ...`). The script prints the geometry, the validation
(`RESULT: OK`, or the problems and nothing is written), the gel-unchanged check, the `slab_data_file_info.md` entry
it appended, and last `DATANAME for the batch file: <stem>`. Next to the input it writes `<stem>.data`, the
no sidecar since 2026-10-28; `--png` draws `<stem>_profiles.png` (density profiles along z and x: check that the gel sits
between the plates and pistons). Copy the `.data` file to `~/Documents/lammps_data/input_data/` on the cluster and
put the stem in the deck's batch (`shear_slab_two_pist_single.batch` for `x_plates`, `compress_slab_single.batch` for
`six_plates`). The periodic-slab converters (`slab_two_pistons_periodic.py`, `slab_shear_plates_periodic.py`) run
the same way; `slab_two_pistons_periodic.ipynb` is kept as their notebook front-end.

### The two-piston converter (2026-09-16)

`slab_two_pistons_periodic.ipynb` is not a lattice generator: it **starts from the equilibrated**
`final_config_slab_support_periodic_…_14000002.data` (the 2026-09-07 piston-transparent rerun) and only
re-arranges the box.  The reason is physical: the two-piston decks hold each reservoir at its pressure with
the NPT-piston scheme of Marioni et al. (J. Membr. Sci. 738 (2026) 124837, Eq. 3), which acts in *z only* —
`lx`, `ly` are fixed for the whole run — so it could never swell a fresh `pre_swell = 0.93` lattice laterally.
Starting from the aniso-NPH slab (σ_p,xx/σ_p,zz = 1.0005) the gel arrives with zero transverse network stress
and its equilibrium `lx`, `ly` and thickness *by construction*; the NPT-piston phase in the decks is then a
z-settle of the reservoirs, not a swelling equilibration.  Gel and solvent coordinates are copied verbatim
(one uniform z shift; the converter checks this).  Output: `<input stem>_two_pist.data` next to the input,
an entry appended to `slab_data_file_info.md` (no `.info.json` sidecar or png since 2026-10-28; `--png` draws the z-density histogram).  Knobs (Config cell / CLI): `permeate_thickness` (10 σ), `feed_thickness` (None =
keep), `margin_perm` (feed + 5 σ), `margin_feed` (15 σ — the feed piston rises by ~strain·L₀ under
compression, so raise it for sweeps beyond ε ≈ 0.10; the converter prints the limit), `piston_clearance`,
`load_piston_frac`, `sheet_source` (`support` copies the input sheet's pattern, 23,316 beads; `hex` rebuilds
at `sheet_spacing`).  If the 14000002 file is not on your Mac the notebook falls back to the 14000000 snapshot
as a **smoke-test input only** and says so.

`shear_slab_two_pist` — one deck since 2026-10-28 (the periodic one is archived). The **isolated-gel deck** (`shear_slab_two_pist.lmp`) reads the **`x_plates` layout** of `lib/add_more_plates_to_gel.py` (on the `slab_with_support_single.batch` final config → `<stem>_x_plates.data`: gel, bath, wet pistons and the two grip plates parked outside the x-faces, which the deck seats and drives); the same notebook with `layout = "six_plates"` builds the `compress_slab` file, and that file runs in the shear deck too (it deletes the four plates it does not use). The archived **periodic deck** (`archive/simulations/shear_slab_two_pist/shear_slab_two_pist_periodic.lmp`, 2026-10-03) needed **no data file of its own**: it reads the `<stem>_two_pist.data` file of `slab_two_pistons_periodic.ipynb` unchanged (the support and the load piston stay parked, the shear is applied through the polymer face layers), so anything built for `triaxial_compression_two_pist` can be sheared as is.

Shear-modulus pipeline **from the periodic slab (the archived `shear_slab` deck, 2026-09-22)**: `python scripts/lib/slab_shear_plates_periodic.py` (defaults point at the 14000002 slab in `lammps_data_files_local/`; knobs `--clearance 0.5 --spacing 1.5 --offset 0.5 --cutoff 2.5 --box-buffer 2.0`) → copy the `*_with_plates.data` it writes to `~/Documents/lammps_data/input_data/` on the cluster → `sbatch shear_slab.batch` (its `DATANAME` already names this file). The plates sit on the slab's z-faces (z = gap, x = shear, the same axes as the compression decks), so the shear gap is the slab thickness (plate separation ~120 σ) and the sheared membrane is laterally periodic (48 × 48 σ). The older isolated-cube pipeline (`isolate_gel.ipynb` → `add_plates_to_gel_periodic.ipynb`, plates on the x-faces of a finite gel driven ±z, 2026-04-28) needs the pre-2026-09-22 revision of `shear_slab.lmp` and the pre-2026-09-23 `shear_analysis.ipynb` (git history).

### Workflow for a new gel

1. Open `data_file_generator.ipynb` (isolated gel; pick `NETWORK`) or `slab_with_support_periodic.ipynb` (x/y-periodic slab; `NETWORK = "tetrahedral" | "random"` since 2026-11-02, code in `lib/periodic_data_file_generator.py`, also a CLI: `python lib/periodic_data_file_generator.py --network random --output <file>` builds `slab_support_periodic_5beads_tall_rho04_random.data`, the reference slab's 9 × 9 × 23 cells with the lattice re-wired by bond switching periodic across x and y — strands and repulsions across the x/y boundaries are minimum-image, only the z faces are tethered; same recipe as the isolated random gel, start = the aligned lattice. It is the random-network input of the two-piston compression deck: `slab_with_support_periodic_random.batch` equilibrates it, `chain_random_periodic.batch` converts and submits; see `scripts/submit_random_periodic_pipeline.sh`).
2. Set the unit-cell count, beads per chain, pre-swell and solvent density.
3. Run all cells. The `.data` file lands in `../../lammps_data_files_local/`; its name encodes the parameters.
4. Copy it to `~/Documents/lammps_data/input_data/` on the cluster and run the equilibration batch.
5. Convert the equilibrated final configuration with the converter the production deck needs (table above).

**Random-network voids fixed (2026-11-03).** The random presets of both builders (`NETWORK = "random"` in `data_file_generator.py` and `periodic_data_file_generator.py`) now relax the junctions with `RANDOM_RELAX = dict(rest_len=1.4, rep_cut=1.3, w_rep=3.0)` (`switch_options` of the preset, passed to `www_bond_switch`). The old relaxation (strand rest length r₀, non-bonded junction repulsion only below 0.9 r₀ at weight 1) pulled the junctions of a random f = 4 network into clumps — a random network wants strands ~1.5 r₀ long at the lattice's junction density, and the harmonic strand energy about r₀ shortened them by piling junctions together — which left 3–5 σ empty spheres and empty 5 σ voxels inside the as-built gel (the periodic `slab_support_periodic_5beads_tall_rho04_random.data` that fed the random triaxial run: polymer density on 5 σ voxels CoV 0.38, emptiest voxel 5 % of the mean, largest empty sphere 4.1 σ; the isolated `slab_support_5beads_tall_rho04_nowalls_random.data`: CoV 0.41, empty voxels, 5.1 σ; the lattice: CoV 0.035–0.05, 1.8 σ; nearest other junction 0.84 r₀ on average, up to 11 junctions within 0.9 r₀). The equilibration run inherits and swells those holes. With the new knobs the strand rest length is the random network's own (1.4 r₀; strands end at 1.43 ± 0.21 r₀ = 2.75 σ, max 1.9) and the repulsion out to 1.3 r₀ spaces the junctions like a soft-sphere liquid: the full periodic slab builds with CoV 0.09, emptiest voxel 70 % of the mean, largest empty sphere 2.1 σ, the junction count within 2 r₀ as uniform as the lattice's (sd 2.0 against 6.7 before and 1.9 for the lattice), isotropy report unchanged (interior OK), no over-long strands, and a uniform 1.2 σ recess of the face junctions (the repulsion of the layer beneath; 1 % of patches dented > 2 σ, the same as before). Both knobs are needed: on a 9 × 9 × 8 test slab `rest_len` 1.4 alone gives CoV 0.34 (the junctions still clump), `rep_cut` 1.3 alone 0.18, `rep_cut` 1.3 at weight 3 alone 0.14, `rest_len` 1.4 + `rep_cut` 1.1 at weight 3 0.19. Also tried and rejected: `w_all` 0.5 (0.27), `rep_cut` 1.5–1.6 at weight 3–5 (0.10, but the face junctions pushed 1.3–1.8 σ in, half the patches dented), `rest_len` 1.4 + `rep_cut` 1.2 (0.13), `w_teth` 8 (0.095, interior isotropy marginal). The isolated random gel (13 × 9 × 30 rot45 cells, the `data_file_generator.py` preset) builds with CoV 0.12, emptiest voxel 58 %, largest empty sphere 2.5 σ (was 0.41, 0 %, 5.1 σ), isotropy OK. The surface line of the isotropy report now measures the recess from the 0.2 / 99.8-percentile planes of the junction cloud and counts separately the junctions that poke more than 1 σ out of them: the new relaxation pushes a few junctions (30 of 15 257 on the isolated block, 5 on the periodic slab) out through a face, and measured from the outermost junction, as before, those read as a 1.2–1.8 σ recess of every patch; against the robust planes the new builds have fewer dents than the old (isolated: 0.46 σ mean, 1.3 % of patches > 2 σ, none > 4 σ, against 0.26 σ, 3.1 % and 0.9 % for the old relaxation; periodic: 0.03 σ and no dents against 0.20 σ, 3 % and 1 %). Every random build now also prints a **density report** (`verify_density_uniformity(<file>, periodic=...)`: polymer density on 5 σ voxels more than 6 σ inside the gel, its CoV and emptiest / fullest voxel, the largest empty sphere from a 0.5 σ grid, the volume more than 3 σ from any bead and how many voids it makes; verdict DENSITY OK at CoV ≤ 0.15 and no 3 σ empty sphere; the voxel, margin and probe scale with a / 4.46 so a longer-strand mesh is judged per mesh). Files built before this date with `NETWORK = "random"` (the random periodic slab and its triaxial run, the isolated random gel and its shear runs, and any beads-per-chain sweep file built before the fix) have the voids; rebuild them. The old relaxation is reproduced with `switch_options={}`.

**Beads-per-chain sweep (2026-11-03).** `python scripts/lib/build_beads_sweep.py [--beads 10 15 20 30] [--dry-run]` builds the periodic random slab for longer strands. The generator's lattice constant is `1.2 (N - 1) pre_swell`, so at fixed cell counts the box grows like N and the atom count like N³; the driver instead keeps the slab at the 5-bead slab's size (~43 σ in plane, ~111 σ thick) by taking fewer cells and a `pre_swell` that puts the lattice at the mesh the gel is expected to swell to (a_eq(N) = 4.82 ((N - 1)/4)^0.59, from the equilibrated 5-bead random slab and the good-solvent exponent). Interior beads go on a random walk between their two junctions (`--chain-placement walk` of `periodic_data_file_generator.py`): on the straight line they would be 0.24-0.4 σ apart. The isotropy report's surface-recess line is calibrated on the 5-bead mesh (4 × 4 σ patches) and reads as voids for a 8-16 σ mesh; ignore it there, the interior verdict is what counts.

**The rot45 periodic slab, the standard gel since 2026-11-07.** `periodic_data_file_generator.py` has a third network, `rot45`: the diamond lattice rotated 45° about y, periodic across x and y, the twin of the isolated rot45 gel of `data_file_generator.py`. The rotated lattice is periodic in the box frame with the body-centred-tetragonal cell a/√2 × a × a/√2, so the slab tiles the box when `units_x` counts BCT cells (a/√2 = 3.73 σ at a = 5.28) and `units_y` cubic cells; `units_z` counts BCT cells too. The sites are the conventional cells rotated and kept in the half-open box ([0, L_x) × [0, L_y)), the bonds are found by the same minimum-image distance search as the aligned lattice (checked on a 6 × 4 × 10 test slab: every interior junction four-coordinated, the (101) face junctions three-coordinated, 204 strands crossing the x/y boundaries). The random networks were too heterogeneous to serve as the example gel; the rotated lattice is the orientation on which the compression side measures (C11 − C12)/2, and longer strands on the same lattice are the route towards a less anisotropic lattice gel. `python scripts/lib/build_beads_sweep.py --network rot45 [--beads 5 15] [--dry-run]` builds `slab_support_periodic_<N>beads_tall_rho04_rot45.data` with: a_eq(N) = 5.28 ((N − 1)/4)^0.59 (the 5-bead lattice's equilibrium constant at P* = 1.5 with the good-solvent exponent — the build starts at a_eq, where the 14000002 slab started at 0.93 × 4.8 and swelled 18 %); in-plane cells for a ~48 σ box (the equilibrated 14000002 slab's 48 × 48); the thickness 1.15 × the reference's 23 cubic cells at a_eq(5) = 139.7 σ rounded up to whole BCT cells (the 2026-11-07 request for ~15 % more height, so that the z-profiles have more bins); straight strands for 5 beads, the random walk for longer ones. The two files built on 2026-11-07: **5 beads** 13 × 9 × 38 BCT cells, box 48.5 × 47.5 × 174.9, lattice 141.9 σ tall (+16.8 % over 23 cells), 18 018 crosslinks, 35 802 strands, 353 825 atoms; **15 beads** 9 × 7 × 18 cells at a_eq 11.06 (pre_swell 0.658), box 70.4 × 77.4 × 173.7, lattice 140.7 σ tall, 4 662 crosslinks, 9 198 strands, 660 402 atoms — the cross-section is 2.4× the 5-bead slab's (`BOX_XY_ROT45_N`: ~74 σ instead of 48) so that the **polymer beads per z-bin match** (124 236 polymer beads over 140.7 σ = 883 per σ, against 884 for the 5-bead file; the 15-bead gel's polymer density at its mesh is 2.4× lower), which keeps the stress and volume-fraction profiles as quiet per bin despite the fewer, floppier chains. The price is 1.9× the atoms of the 5-bead file, so the two-piston runs need about twice the wall time or twice the nodes; the same day's earlier builds (6 × 4 × 18 at 48 σ, 252 k atoms; 7 × 5 × 18 at 55 σ, 367 k, `--box-xy 55`) are the cheaper fallbacks; walk placement: a few hundred bonds start longer than the FENE R₀ of 1.5 σ and some polymer pairs closer than 0.5 σ — the harmonic push-off of `slab_with_support.lmp` Phase 0 takes care of both, as it did for the random sweep files. The lattice constant is the c* estimate; the aniso NPH equilibration sets the real in-plane size, and a gel that swells past a_eq gives a proportionally larger (and more expensive) two-piston box. Equilibrate with `NETWORK=rot45 bash submit_chain_length_sweep.sh [5 15]` (`chain_length_testing_sweep.batch`, aniso NPH at P* = 1.5, Rg-plateau halt; the budgets 14 M / 30 M are the final_config tags), convert the final configuration once per gel with `slab_two_pistons_periodic.py --margin-perm 40` (`<stem>_two_pist_pm40`, read by both two-piston decks) and run `triaxial_compression_two_pist_single.batch` and `triaxial_permeation_two_pist_single.batch` with `DATANAME` exported — or let `chain_random_periodic.batch` do the copy, conversion and submission (`running_simulations.md`).

Every generated file gets an entry in [`slab_data_file_info.md`](../slab_data_file_info.md), and the folder is catalogued in `lammps_data_files_local/README.md` (2026-10-11): one row per file with the measured solvent density, provenance, the batch that used it and its status. Active files stay at the top level; obsolete lineages are in `archive/<date>_<lineage>/`. The `rho` in a raw file's name is the generator's nominal density and was wrong for some files (`rho6` = 1.0; the cubes `new_02` = 0.6, `new_03` = 1.0): the two current ones were renamed to `rho10` (= 1.0) on 2026-10-11.
